# Guilde — plan de construction

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** ajouter l'onglet Guilde (sa guilde, recherche, classement), les grades, les invitations et demandes, et l'XP de guilde.

**Architecture :** une logique pure dans `src/shared/guild.js`, un service serveur en file unique sur une fiche `guilds` (comme `server/social/raffle.js`), un crochet `onXp` dans le service de jeu, un module d'interface `src/ui/guild.js`.

**Tech Stack :** JS vanilla, Node ≥ 20, `node:test`. Aucune dépendance nouvelle.

**Spec :** `docs/superpowers/specs/2026-10-31-guilde-design.md`

## Global Constraints

- Tout se fait dans `F:\dim-prison`, branche `geoffrey/guilde`. Pousser après chaque commit, ne rien mettre en ligne.
- Chaque commit finit par `Par : Geoffrey` et `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Tout est rattaché à l'ID de compte, jamais au pseudo. Le navigateur n'envoie jamais de grade.
- Valeurs dans `src/config.js` : `GUILD = { maxMembers:30, xpPct:1, nameMin:3, nameMax:24, maxInvites:50, maxRequests:50, maxPendingPerPlayer:5, poll:5000 }`.
- Textes en français, tutoiement. Tout pseudo ou nom de guilde affiché passe par `esc`.
- Tests liés seulement (`node --test tests/<sujet>.test.js`) ; rouges déjà connus sur main : table de recherche, roi gobelin, `energyOfTicks`.
- Scripts de modification en fichier Python avec `os.chdir(r'F:\dim-prison')` ; jamais `[IO.File]` avec un chemin relatif.

## Review Focus

1. **Double clic ou deux officiers sur la même demande** : le second appel ne fait rien et renvoie l'état à jour, sans erreur ni doublon (Tâche 2).
2. **Session finie après un départ** : un joueur qui a quitté avant la fin de sa session n'envoie d'XP à aucune guilde ; dans une nouvelle guilde, l'XP va à celle-ci (Tâche 3).
3. **Nom de guilde avec `<script>`, espaces multiples ou majuscules** : affiché sans injection ; `  Les  Rois ` et `les rois` sont le même nom (Tâches 1 et 4).
4. **Compte sans fiche lisible ou pseudo changé** : la liste affiche le pseudo actuel, ou l'ID formaté si le compte n'existe plus, sans planter (Tâche 2).
5. **Fiche abîmée** : `sanitizeGuilds` retire l'entrée invalide, et une guilde sans chef reçoit le plus ancien membre (Tâche 1).
