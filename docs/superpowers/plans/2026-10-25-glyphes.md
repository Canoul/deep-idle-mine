# Glyphes (étape 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ajouter les glyphes (objets posés à côté d'un skill au rang max dans l'onglet Skills) et les effets de 9 glyphes.

**Architecture:** Les glyphes posés vivent dans l'état des skills du joueur (`st.glyphs = { nœud: nom d'objet }`), logique pure
dans `src/meta/glyphs.js`. Le serveur pose / retire sous les verrous inventaire + skills et fige, au lancement d'une session, les
glyphes actifs dans `record.skills[compte].glyphs`. En partie, `skillEffects` ajoute `glyph_<nœud>: 1` dans `m.skill` ; trois
glyphes changent des stats (`withGlyphStats`), six agissent dans la simulation.

**Tech Stack:** JS vanilla (modules ES), Node ≥ 20, `node --test`.

**Spec:** `docs/superpowers/specs/2026-10-25-glyphes-design.md`

## Global Constraints

- Toutes les valeurs dans `GLYPHS` (`src/config.js`), aucune valeur en dur dans la logique (CLAUDE.md §8.4).
- Simulation sans DOM ; le serveur fait foi ; rien n'est rattaché au pseudo (CLAUDE.md §8).
- Anti-triche : quantités / objets invalides refusés, `opId` idempotent, matière conservée (un glyphe : inventaire OU case).
- Pose : skill **au rang max** ; retrait : toujours (hors session) ; reset et sets **ne retirent pas** les glyphes.
- Braum : **à chaque entrée** (dehors → dedans), sans limite. Force brute : dégâts totaux, skills compris.
- Pas de Glyphe Treuil à cette étape. Pas de case pour Légende de la flemme, Escalateur, Provocation.
- Commits : un sujet par commit, message terminé par `Par : Geoffrey` puis la ligne Co-Authored-By ; `git push` après chaque commit ;
  jamais sur `main`.
- Après chaque tâche : seulement les tests du sujet (`node --test tests/<sujet>.test.js`).

## Review Focus

- Retirer un glyphe avec l'inventaire plein : refusé (`inventory_full`), rien ne bouge → test dans Task 2.
- Appliquer un set ou faire un reset avec des glyphes posés : les glyphes restent, inactifs si le skill n'est plus au max → Task 2.
- Enregistrement de session trafiqué (`glyphs` d'un nœud pas au max, nom d'objet faux, `__proto__`) : ignoré → Task 2.
- Second souffle avec le stock de torches plein : jamais au-delà de `carac.torches` → Task 5.
- Braum : un barbare qui reste sur le seuil ne regagne pas d'oxygène à chaque tick (seulement au passage dehors → dedans) → Task 5.

### Task 2: Règles de pose (logique pure)

**Files:**
- Create: `src/meta/glyphs.js`
- Modify: `src/meta/skills.js` (`createSkills` → `glyphs:{}` ; `sanitizeSkills` relit `glyphs` ; `skillEffects` ajoute
  `glyph_<nœud>: 1` pour chaque glyphe actif)
- Test: `tests/glyphs.test.js`, `tests/anticheat/glyphs.test.js` (créé)

**Interfaces:**
- Consumes: `GLYPHS` (Task 1), `addItem/removeItem/countOf` (`src/meta/inventory.js`), `rankOf`, `NODES`.
- Produces:
  - `glyphOf(node) -> string|null` (nom de l'objet du glyphe de ce nœud) ; `nodeOfGlyph(item) -> string|null`.
  - `glyphOp(st, inv, op) -> { ok, repeated } | { error }`, `op = { action:'pose'|'remove', node, opId }`. Erreurs : `bad_request`,
    `unknown` (nœud sans glyphe / inconnu), `not_max`, `occupied`, `not_owned`, `empty`, `inventory_full`. Utilise `st.ops`
    (même mémoire que `skillOp`).
  - `isActive(st, node) -> boolean` (posé et skill au max) ; `activeGlyphs(st) -> { [nœud]: nom }`.
  - `sessionSkills(st) -> { tree, ranks, glyphs: activeGlyphs(st) }` (ce que le serveur fige au lancement).
  - `sanitizeSkills(raw)` garde `glyphs[nœud]` seulement si `glyphOf(nœud) === raw.glyphs[nœud]` (nœud sans glyphe, nom faux,
    clé héritée → ignoré) ; **ne vérifie pas le rang** (un glyphe posé reste posé, inactif).

- [ ] **Step 1: Tests** (dans `tests/glyphs.test.js`) :
  - `pose : skill au max + glyphe dans l'inventaire → case remplie, objet retiré` ; refus `not_max` (rang 2/3), `not_owned`,
    `occupied`, `unknown` (`'taunt'`, `'__proto__'`, `42`), `bad_request` (action inconnue) ; même `opId` rejoué → `repeated`, un seul
    objet retiré.
  - `retrait : objet rendu, case vide ; inventaire plein → inventory_full, rien ne bouge ; case vide → empty`.
  - `reset des skills et set appliqué : glyphes toujours posés, inactifs` : `skillOp(st,{action:'reset'})` puis
    `isActive === false`, `st.glyphs` inchangé ; `applySet` (src/meta/sets.js) avec un set sans ce skill : `st.glyphs` inchangé.
  - `relecture : glyphes trafiqués ignorés` : `sanitizeSkills({ tree:'mineur', ranks:{…}, glyphs:{ ore_rush:'Glyphe Ruée',
    taunt:'Glyphe Pillage', mine_speed:'Charbon', __proto__:{} } })` → seulement `ore_rush`.
  - `skillEffects : glyph_<nœud> seulement si actif` ; `sessionSkills` ne contient que les actifs.
- [ ] **Step 2: Test anti-triche** `tests/anticheat/glyphs.test.js` : 300 suites de 20 opérations au hasard (pose / retrait / opId
  rejoués / nœuds et actions trafiqués / relecture `sanitizeSkills(JSON)` + `deserialize(serialize(inv))`) : pour chaque glyphe,
  `countOf(inv, nom) + (st.glyphs[nœud] === nom ? 1 : 0)` reste égal au départ.
- [ ] **Step 3:** Lancer → FAIL.
- [ ] **Step 4:** Implémenter `src/meta/glyphs.js` et les changements de `skills.js`.
- [ ] **Step 5:** `node --test tests/glyphs.test.js tests/skills.test.js tests/sets.test.js && npm run test:anticheat` → PASS
